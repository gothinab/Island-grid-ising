# grid-ising: живучесть островных энергосетей в модели Изинга

Учебный проект по дисциплине «Моделирование систем и технологий».

Модель Изинга на графе реальной высоковольтной сети Дании. Цель: найти критическую температуру T_c и сравнить профиль фазового перехода с островной сетью Великобритании.

## Постановка задачи

- **Сеть:** `Countries/Denmark/graphml/Denmark_highvoltage.graphml`. Дания топологически является энергетическим островом, без сухопутных связей с другими странами, поэтому стабильность определяется внутренним балансом.
- **Управляющий параметр:** температура T, то есть технологический шум и отказы оборудования.
- **Задача:** найти T_c и сравнить профиль перехода с сетью Великобритании (вариант 4), чтобы выявить общие закономерности «островных» топологий.
- **Датасет:** https://github.com/ComplexNetTSP/Power_grids

## Физическая модель

Каждый узел сети (подстанция) несёт спин s_i = ±1:

- `+1`: узел работает,
- `-1`: узел отказал.

Рёбра графа (линии электропередачи) задают взаимодействие. Энергия системы:

```
H = -J * Σ_{<i,j>} s_i * s_j
```

Температура T играет роль шума. При малых T узлы согласованы (порядок, сеть «жива»), при больших T состояние хаотично. Между ними находится фазовый переход.

Динамика: алгоритм Метрополиса. Выбираем случайный узел, считаем изменение энергии dE = 2·J·s_i·Σ s_j по соседям, переворачиваем спин, если dE ≤ 0 или с вероятностью exp(-dE/T).

### Наблюдаемые

| Величина | Формула |
|---|---|
| Магнитизация | m = (1/N) Σ s_i, считаем ⟨\|m\|⟩ |
| Энергия на спин | e = E / N |
| Восприимчивость | χ = N (⟨m²⟩ − ⟨\|m\|⟩²) / T |
| Теплоёмкость | C = (⟨E²⟩ − ⟨E⟩²) / (N T²) |

**T_c** определяется по положению пиков χ(T) и C(T).

### Проверка корректности

1. **Квадратная решётка** (`scripts/check_lattice.py`): точное решение Онсагера даёт T_c ≈ 2.269 J. Если код на решётке даёт это значение, ядро работает верно.
2. **Теория среднего поля для сетей:** T_c ≈ J · ⟨k²⟩ / ⟨k⟩, где k — степень узла. Это значение сравнивается с результатом симуляции.

### Назначение модулей

| Модуль | Ответственность |
|---|---|
| `graph.py` | Читает graphml через networkx, убирает направления, петли и дубли рёбер, оставляет наибольшую связную компоненту, перенумеровывает узлы в 0..N-1. Переводит граф в CSR-массивы `indptr` и `indices`. Считает топологические характеристики (⟨k⟩, ⟨k²⟩, кластеризация, диаметр). |
| `kernel.py` | Вычислительное ядро на `@njit`. Работает только с numpy-массивами, без networkx. |
| `sweep.py` | Для каждой температуры: разогрев, измерения, подсчёт ⟨\|m\|⟩, ⟨E⟩, χ, C. Возвращает массивы и положение T_c. |
| `plots.py` | M(T), χ(T), C(T), сравнение двух сетей. |

### Поток данных

```
graphml ──► graph.py ──► CSR-массивы ──► kernel.py ◄── sweep.py ──► results/*.npz ──► plots.py ──► report.ipynb
         (networkx)    (indptr, indices)  (numba)    (цикл по T)
```

Зависимости направлены в одну сторону: `scripts` → `sweep` → `kernel` / `graph`. Благодаря этому каждую часть можно тестировать отдельно.

### Формат CSR

Соседи узла `i` лежат в `indices[indptr[i] : indptr[i+1]]`, степень узла равна `indptr[i+1] - indptr[i]`. Этот формат numba обрабатывает быстро, а объекты networkx в `@njit`-функциях использовать нельзя.

## Как работает расчёт

1. `graph.py` загружает граф и готовит CSR-массивы.
2. Спины инициализируются случайно: `spins = np.random.choice([1, -1], size=N)`.
3. Для каждой T из сетки (например, 0.1 … 10, 60 точек):
   - **разогрев:** несколько тысяч шагов Метрополиса без записи, чтобы система вышла на равновесие;
   - **измерения:** несколько тысяч шагов, на каждом (или через несколько шагов) записываются |m| и E;
   - усреднение и подсчёт χ, C.
4. T_c берётся как положение максимума χ(T) (и сверяется с максимумом C(T)).
5. То же для второй сети, затем сравнение профилей и топологических характеристик.

Один шаг Метрополиса — это N попыток переворота случайных узлов, то есть один «проход» по сети.

## Параметры

| Параметр | Смысл | Типичное значение |
|---|---|---|
| `J` | константа связи | 1.0 |
| `T_min`, `T_max` | диапазон температур | 0.1 … 10 |
| `n_points` | число точек по T | 60 |
| `n_equil` | шагов разогрева | 2000 |
| `n_measure` | шагов измерения | 5000 |
| `seed` | зерно генератора | 42 |

Вблизи T_c стоит сгустить сетку температур и увеличить число шагов: там система релаксирует медленнее всего.
