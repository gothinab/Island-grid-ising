# grid-ising: живучесть островных энергосетей в модели Изинга

Учебный проект по дисциплине «Моделирование систем и технологий».

Модель Изинга на графе реальной высоковольтной сети Дании. Цель: найти критическую температуру T_c и сравнить профиль фазового перехода с островной сетью Великобритании.

## Постановка задачи

- **Сеть:** `Countries/Denmark/graphml/Denmark_highvoltage.graphml`. Дания топологически является энергетическим островом, без сухопутных связей с другими странами, поэтому стабильность определяется внутренним балансом.
- **Управляющий параметр:** температура T, то есть технологический шум и отказы оборудования.
- **Задача:** найти T_c и сравнить профиль перехода с сетью Великобритании (вариант 4), чтобы выявить общие закономерности «островных» топологий.
- **Датасет:** https://github.com/ComplexNetTSP/Power_grids

## Физическая модель

Каждый узел сети (подстанция) несёт спин s_i = ±1:

- `+1`: узел работает,
- `-1`: узел отказал.

Рёбра графа (линии электропередачи) задают взаимодействие. Энергия системы:

```
H = -J * Σ_{<i,j>} s_i * s_j
```

Температура T играет роль шума. При малых T узлы согласованы (порядок, сеть «жива»), при больших T состояние хаотично. Между ними находится фазовый переход.

Динамика: алгоритм Метрополиса. Выбираем случайный узел, считаем изменение энергии dE = 2·J·s_i·Σ s_j по соседям, переворачиваем спин, если dE ≤ 0 или с вероятностью exp(-dE/T).

### Наблюдаемые

| Величина | Формула |
|---|---|
| Магнитизация | m = (1/N) Σ s_i, считаем ⟨\|m\|⟩ |
| Энергия на спин | e = E / N |
| Восприимчивость | χ = N (⟨m²⟩ − ⟨\|m\|⟩²) / T |
| Теплоёмкость | C = (⟨E²⟩ − ⟨E⟩²) / (N T²) |

**T_c** определяется по положению пиков χ(T) и C(T).

### Назначение модулей

| Модуль | Ответственность |
|---|---|
| `cli.py` | Разбирает аргументы командной строки, загружает граф, запускает расчёт и рисует графики. Логики расчёта в нём нет. |
| `config.py` | Пути (`DATA_DIR`, `RESULTS_DIR`), параметры симуляции по умолчанию (`SIM`), настройки графиков (`PLOT`). |
| `simulation.py` | `run_simulation`: для каждой температуры разогрев и измерения, возвращает ⟨E⟩ и ⟨E²⟩. |
| `core/physics.py` | Вычислительное ядро на `@njit`: `metropolis_step_graph`, `calculate_energy_graph`. Работает только с массивами numba, без networkx. |
| `data_io/loader.py` | Класс `NetworkFaultTolerance`: читает граф networkx и строит для каждого узла массивы соседей и весов, считает `mean_degree`. |
| `visualization/plots.py` | `plot_energy`, `plot_heat_capacity`, `plot_thermodynamics`. Принимают готовые данные и ничего не считают. |
| `ui/app.py` | Точка входа интерфейса (Streamlit): боковая панель с параметрами, сборка страницы и вкладок. |
| `ui/services.py` | Загрузка графа и расчёты с кэшированием, состояние сети при заданной температуре, координаты узлов. Без отрисовки. |
| `ui/charts.py` | Фигуры Plotly: графики E(T) и C(T) с перекрестием, карта сети. |
| `ui/tabs.py` | Содержимое вкладок «Термодинамика», «Карта сети», «О модели». |
| `ui/components.py`, `ui/theme.py` | Карточки, шапка, подвал; палитра и CSS. |

### Поток данных


## Установка и запуск

Нужен только [Docker](https://docs.docker.com/get-docker/) с Compose (на Windows: Docker Desktop с WSL2). Python и зависимости ставить не нужно: всё собирается внутри образа.

### 1. Клонировать репозиторий

```powershell
git clone <url-репозитория>
cd ising_model
```

### 2. Положить данные

Скачайте graphml-файлы из репозитория https://github.com/ComplexNetTSP/Power_grids (кнопка Raw) и положите в `data/`:

```
data/Denmark_highvoltage.graphml
data/<файл Великобритании>.graphml
```

Папка `data/` подключается к контейнеру с вашего диска и в образ не попадает.

### 3. Запустить

```powershell
docker compose up --build
```

Откройте http://localhost:8501. Параметры расчёта задаются в боковой панели, результаты показываются на вкладках.

Первая сборка занимает несколько минут: ставятся scipy, numba, plotly. Следующие запуски быстрее:

```powershell
docker compose up
```

Остановить: `Ctrl+C` или `docker compose down`. Запуск в фоне: `docker compose up -d`.

Первый расчёт в интерфейсе начинается с компиляции numba-ядра, это займёт несколько секунд.

### Расчёт из терминала

Без интерфейса, в том же образе. В контейнере нет экрана, поэтому всегда указывайте `--no-show`: график сохраняется в `results/` на вашем диске.

Быстрая проверка с маленькими параметрами:

```powershell
docker compose run --rm app ising-model --n-temps 5 --steps-thermal 100 --steps-measure 100 --no-show
```

Если в `results/` появился файл `Denmark_highvoltage_thermo.png`, всё работает.

Основной расчёт для Дании с параметрами по умолчанию:

```powershell
docker compose run --rm app ising-model --no-show
```

### Параметры командной строки

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `--graph` | имя файла из папки `data/` | `Denmark_highvoltage.graphml` |
| `--n-temps` | число точек по температуре | 30 |
| `--steps-thermal` | шагов разогрева | 2000 |
| `--steps-measure` | шагов измерения | 3000 |

Примеры:

```powershell
# другая сеть

# подробный расчёт
docker compose run --rm app ising-model --n-temps 60 --steps-thermal 5000 --steps-measure 10000 --no-show
```

```powershell
docker compose run --rm -v ./scripts:/app/scripts:ro app python scripts/check_lattice.py
```

Должно получиться T_c ≈ 2.27.

### Настройка параметров по умолчанию

Значения по умолчанию лежат в `src/grid_ising/config.py`: число температур, шаги, границы диапазона температур (в долях T_c), цвета и размер графиков. Код копируется в образ при сборке, поэтому после любой правки в `src/` пересоберите образ:

```powershell
docker compose up --build
```

## Как работает расчёт

1. `loader.py` загружает граф и строит для каждого узла массивы соседей.
2. Спины инициализируются случайно: `spins = np.random.choice([1, -1], size=N)`.
3. Для каждой T из сетки (диапазон задаётся долями от теоретического T_c):
   - **разогрев:** несколько тысяч шагов Метрополиса без записи, чтобы система вышла на равновесие;
   - **измерения:** несколько тысяч шагов, на каждом записывается E;
   - усреднение и подсчёт теплоёмкости C.
4. T_c оценивается по положению максимума C(T) (и χ(T), когда она будет реализована).
5. То же для второй сети, затем сравнение профилей и топологических характеристик.

Один шаг Метрополиса — это N попыток переворота случайных узлов, то есть один «проход» по сети.

Вблизи T_c стоит сгустить сетку температур и увеличить число шагов: там система релаксирует медленнее всего.

Для работы с ноутбуками из `notebooks/` понадобится локальное окружение. Нужен [uv](https://docs.astral.sh/uv/):

```powershell
uv sync
```

## Возможные проблемы

| Ошибка | Причина и решение |
|---|---|
| `error during connect` или Docker не отвечает | Не запущен Docker Desktop. |
| `port is already allocated` (порт 8501 занят) | Закройте другой Streamlit или поменяйте порт в `docker-compose.yml`: `"8502:8501"`. |
| В интерфейсе «нет файлов .graphml» | Папка `data/` пуста или лежит не в корне проекта. |
| `uv sync --frozen` падает при сборке | `uv.lock` не соответствует `pyproject.toml`. Выполните `uv lock` локально и закоммитьте файл. |
| Не находится подходящий Python | Версия в первой строке `Dockerfile` не совпадает с `requires-python` в `pyproject.toml`. |
| Сборка падает из-за пути с кириллицей | Переместите проект в папку с латинским названием. |
| Изменения в коде не видны | Образ нужно пересобрать: `docker compose up --build`. |
